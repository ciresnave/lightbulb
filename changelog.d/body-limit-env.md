kind: **BREAKING**: `ApiConfig::max_request_body_bytes`, `InferenceJob::seed`, `InferenceJob::extras` and a `SchedulerDriver::try_admit` argument added; `LIGHTBULB_MAX_REQUEST_BODY_BYTES`; per-request `seed` (ROADMAP A7, A5)
---
The request-body cap (still 2 MiB by default, 413 above it) is now configurable: `ApiConfig` gains a public field `max_request_body_bytes`, set from `LIGHTBULB_MAX_REQUEST_BODY_BYTES` (whole number of bytes of at least 1; `0` or a non-number refuses to start, as `LIGHTBULB_AUDIT_RETENTION_DAYS` does). A struct literal of `ApiConfig` without `..Default::default()` stops compiling. Tests: the parser (blank, number, 0, text, negative) and one route answering 200 under a larger cap and 413 under a smaller one with the same body. `docs/CONFIGURATION.md` lists the variable (36 names, 0 missing, 0 extra against `git grep` of `src/`).

Also in this entry (ROADMAP A5): the OpenAI `seed` request field on `/v1/chat/completions` and `/v1/completions`. With `temperature > 0`, the same seed, prompt and settings reproduce the same tokens on the same build and device; greedy ignores it; a negative value is reinterpreted as `u64`; chat `n` runs take `seed + i` so the choices differ yet reproduce. `ChatCompletionRequest`, `CompletionRequest` and `InferenceJob` each gain a public `seed` field, so a struct literal of any of them without `..Default::default()` (or, for `InferenceJob`, with no such option) stops compiling. Verified by three tests with a mutation each: the paged driver (same seed reproduces, other seeds differ, greedy unaffected; mutated to ignore the seed, the reproduce test fails), the runner (`job.seed` reaches `try_admit`), and the HTTP layer (plain, streaming, `n=3` giving 40/41/42, negative; the `n` offset and the streaming literal each mutated, each fails). The `ApiServer` router now also has a test that the configured body cap is the one enforced (mutated to the constant, it fails with 200 for 413). Not covered: a real GGUF model reproducing under a seed (needs a GPU/model slot).

Also (ROADMAP A5): `top_p`, `presence_penalty` and `frequency_penalty` on `/v1/chat/completions` and `/v1/completions` now take effect instead of `top_p != 1` being a 400. `top_p` must be in `(0, 1]` and each penalty in `[-2, 2]`, else 400; a request using none of them takes the unchanged sampling path. They reach Fuel's `add_session_with_params` via a new `SamplingExtras` on `InferenceJob` and a new `extras` argument of `SchedulerDriver::try_admit`, so `InferenceJob` literals and `SchedulerDriver` impls need updating (BREAKING). Six mutants (driver ignores extras, drops `top_p`, drops the presence penalty, API drops `top_p`, runner drops `job.extras`, no range check) each fail the tests on the matching assertion. Still unsupported: `logit_bias`, `top_k`, `min_p`, repetition penalty, `logprobs`. Not covered: a real GGUF model under these settings (needs a GPU/model slot).

Dependencies: mlmf-gguf, mlmf-source-hub and mlmf-hf-layout 0.11.29 -> 0.11.49 (includes source-hub bearer-token Debug redaction).
