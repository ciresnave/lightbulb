---
The three `#[ignore]`d `loader_f32` tests (`every_weight_is_f32`, `f32_and_stock_loaders_agree`, `loader_surfaces_eos_and_tokenizer`) and `stepwise_logits_match_the_reference_loop_exactly` now run on the synthetic checkpoint instead of needing a downloaded TinyLlama; they assert loader plumbing, not trained values. Test-only. `fuel_runner_serves_a_default_temperature_completion` (`fuel_engine_http`) also runs on it, in a new CI step (`synthetic`, `--features fuel-engine`); its request named model `tinyllama`, which the server refuses (400), so it could not have passed even with the real checkpoint: fixed to `lightbulb-default` in both tests of that file. `plan_once_vs_replan` (`paged_plan_once`) runs on it as a wiring check (both arms decode, the control holds no plan, the flag takes); its timings are of a toy model. `loads_a_synthetic_checkpoint_from_a_local_dir` (`loader.rs`) is the same load-and-check-config test on the fixture, added beside the ignored real-TinyLlama one, which keeps the real-value assertions. A shared synthetic GGUF header writer (`tests/support/gguf.rs`, moved out of `chat_template_render.rs`, which now uses it) lets `two_runs_over_a_synthetic_corpus_are_byte_identical` run the metadata dump's determinism check without a corpus. `the_sweep_runs_clean_over_a_synthetic_gguf` runs the metadata sibling sweep over one synthetic file (plumbing only; real checkpoints still need the corpus). `an_unverified_pre_tokenizer_is_refused_by_name_on_a_synthetic_gguf` runs the unverified-`pre` refusal on a header-only GGUF (control: a verified `pre` there makes it fail). `the_dtype_gap_guard_holds_over_synthetic_one_tensor_files` runs the dtype-table guard over one-tensor header-only files (the shared writer gained `gguf_bytes_with_tensor`; a dtype outside the table makes it fail).
