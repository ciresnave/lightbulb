---
`logprobs` / `top_logprobs` (chat, `0..=20`) and `logprobs: N` (completions, `0..=20`) now return each generated token's log-probability and its best alternatives, from Fuel's per-session `SamplingParams::logprobs` (values are under the model's own distribution, before temperature, filters and penalties). Chat gets `choices[].logprobs.content[]`, completions get the parallel-array shape with `text_offset`; a stop sequence cuts the entries with the text. Non-streaming only: `logprobs` with `stream`, `response_format` or `lightbulb.output_contract` (chat), and with `echo` (completions), is a 400, as are `top_logprobs` without `logprobs: true` and values above 20. `logit_bias` still has no Fuel type. Verified by a real-Fuel tiny-model driver test (one entry per generated token, greedy picks the top alternative, a session that did not ask records none), a runner mapping test, and handler tests for both endpoints; a real GGUF run is not covered.

- **Review fixes (Pip, #335):** logprob entries now carry `text_len`, the bytes each token adds to the decoded text (a character split across tokens is counted whole), so a stop sequence or a tool call that shortens the returned content drops the entries it cuts or passes, and `text_offset` follows the text. Chat logprobs are built from the content actually returned.

**A4 (tool-call history).** When a request offers `tools` and the checkpoint's own chat template renders them, the conversation now reaches the template with the assistant's earlier `tool_calls` (arguments as an object, as `transformers` passes them) and each tool result's `tool_call_id` and `name`, not only `role` and `content`; before, a follow-up turn that carried a tool result rendered the call and its result as bare text. New `ChatTemplate::render_json_with_tools` takes HF-shaped message values; `render_with_tools` delegates to it and renders as before. Verified on a hand-written template (history reaches it; a history without tool turns renders unchanged) and by dropping the `tool_calls` conversion, which fails the test; not checked against a real model's template on a multi-turn tool conversation. A message's `name` is now passed to the template whenever the request supplies one (HF does the same).
