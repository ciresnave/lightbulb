kind: F3: `POST /v1/embeddings` serving nomic-embed-text-v1.5 (safetensors), with Matryoshka `dimensions`
---
`POST /v1/embeddings` is live over the slice-1 core. A models directory may now hold an embedding model as a DIRECTORY of Hugging Face files (`model.safetensors`, `tokenizer.json`, `config.json` with `model_type: nomic_bert`); the manager loads it on demand and evicts it like a chat model, `GET /v1/models` lists it with `lightbulb_kind: "embedding"` (a chat model's JSON is unchanged), and a request naming a chat model, or a chat request naming an embedding model, is a 400 that says so. Only nomic-embed-text-v1.5 is supported (a directory of any other architecture is neither listed nor loaded); Ollama's GGUF embedders are NOT loadable (Fuel has no GGUF encoder path). Errors: 400 for a bad request (unknown model, wrong kind, token-id input, empty or over-long input, a bad `encoding_format`, a `dimensions` the model was not trained for), 500 for a model-side failure (a non-finite vector, a wrong width). Credit: the model is nomic-ai/nomic-embed-text-v1.5 by Nomic AI, Apache-2.0, https://huggingface.co/nomic-ai/nomic-embed-text-v1.5; the weights are never in this repository.

**Fixed in passing (found while adding the embedding kind):** `ModelRegistry::entry()`, the lookup every chat handler uses, returned the first entry by name, so an embedding model that sorts before the chat model would have answered chat requests with no runner. It now skips embedding entries (a test goes red without the filter).

`dimensions` follows the model card (README.md at revision e9b6763023c6, lines 2676-2734): layer-norm the FULL 768 vector (no affine, eps 1e-5), slice, L2; the native width is mean pooling then L2 with no layer norm. Widths 64, 128, 256, 512.

**Verified (local, not in hosted CI):** against reference vectors from the model's own fp32 ONNX export run by onnxruntime 1.32.0 (not sentence-transformers with `trust_remote_code`; `tools/gen-nomic-reference.py`, fixture `tests/fixtures/nomic-embed-text-v1.5-reference.json`, checkpoint revision e9b6763023c6, sha256 in its PROVENANCE.txt): all 5 sentences reach cosine 1.000000 at 768, and all 20 sentence-by-width pairs reach >= 0.999 at 64/128/256/512; a pooling control (CLS 0.90-0.94, last-token 0.85-0.91 against the mean's 1.0); position invariance and summed usage; and the whole server path (models directory, manager loading on demand, the route, `/v1/models`) over the real checkpoint, cosine 1.000000. CPU, f32, debug build, Windows; 5 short sentences.

**Not verified, and limits:** hosted CI has no checkpoint, so `tests/nomic_reference.rs` skips there with a printed reason (a failure under `LIGHTBULB_REQUIRE_MODEL=1`; a failure, never a skip, when `NOMIC_EMBED_DIR` is set but incomplete); no CI download was added. The tokenizer shares its method with the reference (the same `tokenizer.json`), so it is cross-checked by token count only. The layer norm changes the cosine by only about 1e-5 on these sentences, so the reference comparison cannot prove that step is present; a hand-computed unit test pins it. No GPU run, no long inputs, no batching beyond a loop of single sequences.
