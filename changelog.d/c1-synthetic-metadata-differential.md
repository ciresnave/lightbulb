kind: C1 the metadata differential runs on synthetic GGUFs
---
The differential test between our GGUF metadata reader and the loaders (`our_metadata_agrees_with_the_loaders_on_synthetic_files`) now has a counterpart that needs no corpus: it writes an F32, Q8_0, Q4_0, Q6_K, templated and chain-output synthetic file and requires both readers to read each and agree key for key (exact count, so an unreadable file fails instead of being skipped). Adding an unreadable file turns it red. The corpus version stays `#[ignore]`d for real files. `the_derivation_never_misses_a_declared_merge_and_over_generates` pins the merge derivation's two measured properties on a hand-checkable vocabulary (never misses a declared merge, over-generates the other valid split), without a corpus; a derivation skipping one-character splits turns it red. Also adds `docs/SELF_HOSTED_TESTS.md` and ROADMAP row C1b: the design for running the real-model `#[ignore]`d tests on the self-hosted runner (environment-gated via `LIGHTBULB_REQUIRE_MODEL` / `LIGHTBULB_REQUIRE_CORPUS`, paths only, a passed-count check, a dispatch-first workflow). Design only; nothing is built. The 12 corpus tests of `spm_derivation_tests` are no longer `#[ignore]`d: they skip without a corpus and fail under `LIGHTBULB_REQUIRE_CORPUS=1`. A new CI gate (`scripts/ignore_census.py`, `docs/ignore-count.txt`) fails when the `#[ignore]` count changes without the recorded number. `selfhosted.yml` is written, dispatch-only and unregistered: it cannot run until a runner exists.
