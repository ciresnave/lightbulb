kind: **BREAKING**: `ApiConfig.model_prefix_retention_blocks` and `EngineOptions.prefix_retention_blocks` added; prefix retention slices 1-4 (off by default)
---
Prompt prefixes can outlive their donor: `model_fuel::prefix_retention` (`PrefixSource`, a bounded LRU `RetainedStore` that evicts deepest-first so a chain stays prefix-closed, typed refusals that evict nothing), `BlockPrefixIndexFor::with_seed` (model/adapter identity in the chain key; empty seed = the existing key), and `adopt`/`owned_by`/`remove_key_owned`. The serving driver queues a finished-prompt chain and, after each step, registers it with Fuel's `register_prefix` (a refusal means the blocks are not filled yet and leaves the pool untouched, so the deepest registration is the readiness probe), then moves the index entries from the live donor to the retained chain so `mirror_departure`'s `forget_donor` no longer ends reuse. The budget is 0 at every construction site today (retention OFF, behaviour unchanged); the env var, eviction under pool pressure and measurements are slices 3-5 (`docs/PREFIX-CACHE-DESIGN.md`).

Verified: 7 store/key unit tests plus 3 driver tests (a second identical prompt after the donor finished takes a real splice with a completion bit-identical to a cold one; control: retention 0 is a cold admit; `cache_clear` drops the retained prefixes). Mutants: shallow-first eviction and never-evicting each fail 2 store tests; skipping the index hand-over fails the driver test. Not measured: any TTFT or GPU number.

Slice 3 (same fragment): eviction under pool pressure. Fuel's paged admission is optimistic (exhaustion surfaces as that session's `Failed`), so `try_admit` checks free blocks up front and evicts retained prefixes LRU-first, deepest first, until the request fits (`a_live_request_evicts_retained_prefixes_instead_of_failing`; control: the same tight pool without the rule fails the request; a request that fits evicts nothing; removing the rule fails the first test). Known limit: a prompt whose session finishes in its prefill step (`max_new` 1) is never retained.

Slice 4: `LIGHTBULB_PREFIX_RETENTION_BLOCKS` (default 0 = off; needs `LIGHTBULB_PREFIX_SHARING`; a bad value or a count without sharing stops startup), plumbed through `ApiConfig`, `StartParams` and `EngineOptions` to the driver (0 for models where sharing is refused, e.g. hybrids). `cache_stats` `entries`/`evictions` follow retained entries; an admin read of pinned blocks is not built. The chain key is the token chain: one driver serves one model with its own pool and no adapter exists in the serving path, so no cross-model or cross-adapter hit is possible today; `BlockPrefixIndexFor::with_seed` is there for when one does.

**Migration:** `ApiConfig` literals add `model_prefix_retention_blocks: 0` or end with `..ApiConfig::default()`; `EngineOptions` literals add `prefix_retention_blocks: 0` or use `..Default::default()`.
