# M4.1 Model Loading Integration - Implementation Summary

## Overview
Successfully integrated TensorNameMapper into the GGUF model loading pipeline to enable architecture-agnostic model loading. This allows Lightbulb to load models from different architectures (LLaMA, GPT, Mistral, etc.) without code changes.

## Implementation Date
January 2026

## Changes Made

### 1. Loader Integration (`src/loaders.rs`)
Added name mapper creation during GGUF loading:
```rust
// Build name mapper for architecture-agnostic tensor loading
use crate::pruning::name_mapping::TensorNameMapper;
let tensor_names: Vec<String> = gguf_content
    .tensor_infos()
    .keys()
    .cloned()
    .collect();
let name_mapper = TensorNameMapper::from_tensor_names(&tensor_names)
    .context("Failed to build tensor name mapper")?;

println!("🔍 Detected model architecture: {:?}", name_mapper.architecture);
```

### 2. Parallel Model Manager (`src/model/parallel_model_manager.rs`)
- Added `Context` trait import from `anyhow`
- Created name mapper before model construction
- Logs detected architecture to console
- Passes name mapper to `BatchedTransformer::from_gguf()`

### 3. Custom Transformer (`src/model/custom_transformer.rs`)
Updated `from_gguf()` to accept and use name mapper:
- Added `name_mapper` parameter
- Maps abstract names to concrete architecture-specific names:
  * `"embedding.weight"` → `"token_embd.weight"` (LLaMA) or equivalent
  * `"output.normalization"` → `"output_norm.weight"` (LLaMA) or equivalent
  * `"output.projection"` → `"output.weight"` (LLaMA) or equivalent
- Falls back to LLaMA names if mapping fails
- Passes mapper to child components

### 4. Transformer Block (`src/model/custom_transformer_block.rs`)
Updated `from_gguf()` to use name mapping for layer components:
- Added `name_mapper` parameter
- Maps layer-specific names:
  * `"layer_{N}.attention.normalization"` → `"blk.{N}.attn_norm.weight"` (LLaMA)
  * `"layer_{N}.ffn.normalization"` → `"blk.{N}.ffn_norm.weight"` (LLaMA)
- Passes mapper to attention and MLP loaders

### 5. Attention Layer (`src/model/custom_attention.rs`)
Updated `from_gguf()` to map attention projection names:
- Added `name_mapper` parameter
- Maps all attention projections:
  * `"layer_{N}.attention.query"` → `"blk.{N}.attn_q.weight"` (LLaMA)
  * `"layer_{N}.attention.key"` → `"blk.{N}.attn_k.weight"` (LLaMA)
  * `"layer_{N}.attention.value"` → `"blk.{N}.attn_v.weight"` (LLaMA)
  * `"layer_{N}.attention.output"` → `"blk.{N}.attn_output.weight"` (LLaMA)

### 6. MLP Layer (`src/model/mlp_wrapper.rs`)
Updated `from_gguf()` to map feed-forward network names:
- Added `name_mapper` parameter
- Maps FFN components:
  * `"layer_{N}.ffn.gate"` → `"blk.{N}.ffn_gate.weight"` (LLaMA)
  * `"layer_{N}.ffn.up"` → `"blk.{N}.ffn_up.weight"` (LLaMA)
  * `"layer_{N}.ffn.down"` → `"blk.{N}.ffn_down.weight"` (LLaMA)

## Architecture Support

### Currently Supported (via TensorNameMapper)
1. **LLaMA** - Primary pattern: `blk.{N}.component.weight`
2. **GPT** - Pattern: `h.{N}.component.weight` (fused QKV)
3. **Mistral** - Pattern: `layers.{N}.component.weight`
4. **Unknown** - Falls back to LLaMA naming convention

### Abstract Name Format
Standardized abstract names used throughout:
- Global: `"embedding.weight"`, `"output.normalization"`, `"output.projection"`
- Per-layer: `"layer_{N}.{component}.{subcomponent}"`
- Components: `attention`, `ffn`
- Subcomponents: `query`, `key`, `value`, `output`, `gate`, `up`, `down`, `normalization`

## Usage Example

When loading a GGUF model, the system now:
1. Extracts all tensor names from the GGUF file
2. Builds a `TensorNameMapper` and auto-detects architecture
3. Logs detected architecture: `🔍 Detected model architecture: LLaMA`
4. Uses mapped names throughout loading process
5. Falls back gracefully to LLaMA names for unknown architectures
