# Fuel/MLMF move manifest — lightbulb

**Measured at:** lightbulb `origin/main` `32e91fc3`, fuel `origin/main` `5bd79337`, mlmf `origin/main` `62c1f6e7`. All reads via `git -C <repo> show/ls-tree origin/main:<path>` — never a working tree.

**Method:** two prior lightbulb docs (`docs/FUEL-CAPABILITY-AUDIT-2026-09-24.md`, `docs/FUEL-PORT-STATUS-2026-09-24.md`) and mlmf's own `docs/fuel-migration-inventory.md` (written 2026-09-30, mlmf-side, extremely thorough on format/file concerns) already contain most of this work. This manifest starts from them but re-verifies every module path against **current** fuel origin/main, since fuel dissolved its monolithic `fuel-core` into ~35 crates since 2026-09-24 (`fuel-model-llama`, `fuel-transformers`, `fuel-loaders`, `fuel-parallel`, `fuel-quantized`, `fuel-nn`, `fuel-inference` etc. are now separate crates — confirmed via `git -C fuel ls-tree origin/main`, top level, 35 `fuel-*` directories plus the `fuel` facade). Where mlmf's own inventory doc already answers a row in more depth than could be re-derived here, it is cited directly rather than re-derived — it is the authoritative source for format/file-loading questions.

Layering rule: mlmf = model-file loading/saving. fuel = building/running models (kernels, quantization math, parallelism, NN modules). lightbulb = serving only (api, server, tls, tools, contracts, engine scheduling/batching, cache **policies**, sampling, hardware/model **selection**, memory planning).
