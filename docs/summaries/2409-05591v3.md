
# 2409.05591v3 — Hardware-aware Attention Schedules

TL;DR

Proposes attention scheduling strategies that adapt attention computation to hardware characteristics (cache sizes, vector width, bandwidth) and input properties (sequence length, layer depth) to reduce memory footprint and improve throughput with minimal accuracy loss. Practical thresholds (e.g., switch to blocked/hybrid kernels for seq len > ~1024) are suggested to improve CPU throughput with modest accuracy trade-offs.

Why it matters for Lightbulb

- Hardware-aware scheduling unlocks large improvements in CPU inference throughput, critical for a Candle-first CPU-focused runtime like `lightbulb`.
- We aim for CPU-first, high-throughput inference. Hardware-aware kernel selection can deliver major latency/throughput wins without modifying model weights. This influences `kernels.rs` and the scheduler's kernel-selection logic.
- The paper's heuristics map cleanly to blocked attention and kernel tiling decisions.

Key technical takeaways

1. Tile sizes tuned to L1/L2 cache footprints reduce cache-line thrashing and memory bandwidth pressure.
2. Smaller vector widths (e.g., int8 kernels) change the optimal blocking factor; schedules must be quantization-aware.
3. Dynamic schedule selection at runtime (using a short micro-benchmark) recovers much of the static tuning benefits while remaining portable.
4. Combining blocked attention with attention pruning (structured sparsity) yields multiplicative throughput gains for long contexts.
5. Practical thresholds (e.g., switch to blocked/hybrid kernels for seq len > ~1024) can be used to improve throughput with modest accuracy trade-offs.

Actions / Implementation steps for lightbulb

1. Add a micro-benchmarking profile that runs at startup to detect cache sizes and vector widths.
2. Implement blocked-attention tiling in the kernel layer and expose multiple tile strategies.
3. Add a runtime scheduler mode that selects tile sizes based on the micro-benchmark results and model quantization settings.
4. Prototype a hybrid attention scheduler in `kernels/` that selects between at least two attention implementations based on sequence length and layer depth.
5. Add microbenchmarks under `bench/` that measure throughput and memory use for selected blocking parameters; include a small accuracy check (toy perplexity) to measure regressions.
6. Add a short developer note `docs/kernels/attention-scheduling.md` summarizing recommended heuristics and thresholds for CPU targets.
7. Experiment with combining blocking + structured sparsity and add a runtime switch to enable hybrid mode.

Acceptance criteria

- Demonstrate >10% reduction in end-to-end latency on representative CPU targets for long sequences, with equivalent perplexity.
- Add unit/integration tests that verify blocked-attention produces numerically-consistent outputs vs a dense baseline on small inputs.
- `kernels` exposes a kernel selector with runtime thresholds and a bench showing >=1.2x throughput on long sequences with <1% toy-task perplexity degradation.
- `docs/kernels/attention-scheduling.md` added with recommended heuristics and a plan for runtime autotuning.
