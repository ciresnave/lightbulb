
# 2508.15126v1 — Scheduler Preemption Strategies

TL;DR

- Strategies for preempting long-running inference requests in schedulers to improve tail latency and fairness. Analysis of preemption and priority scheduling strategies for low-latency inference workloads with mixed request sizes.

Why it matters

- For CPU-first runtimes, a smart preemption policy reduces stragglers and improves percentile latency without sacrificing throughput.
- Provides algorithms for fair latency-aware preemption useful for the lightbulb request scheduler when running on shared CPUs.

Key takeaways

- Lightweight checkpoint points + cooperative yielding outperform heavy-weight context switches for short requests.
- Prioritization by remaining work estimate (model tokens × compute per token) helps reduce 95th/99th percentiles.
- Authors propose a hybrid early-exit + preemption approach for elastic batching.

Actions / Implementation steps for lightbulb

1. Implement a cooperative yield API in the scheduler for long-running tasks.
2. Add an estimator for remaining work and a policy to preempt low-priority tasks.
3. Add metrics to measure tail latency and fairness across workloads.
4. Implement a simple token-count-based preemption policy in the scheduler prototype.
5. Simulate mixed small/large request workloads and measure tail-latency improvements.

Acceptance criteria

- Scheduler demonstrates reduced 95th-latency on synthetic workloads by 15–30% with minimal throughput loss.
- Scheduler reduces 95th-percentile latency by >=20% in simulated mixed workloads without hurting average throughput by more than 5%.
