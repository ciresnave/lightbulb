
# 2409.05591v3 — Hardware-aware attention schedules (research note)

TL;DR

This note proposes attention-kernel switching and blocking heuristics that are tuned to hardware characteristics (cache, bandwidth) and input properties (sequence length, layer depth). Practical thresholds (e.g., switch to blocked/hybrid kernels for seq len > ~1024) are suggested to improve CPU throughput with modest accuracy trade-offs.

Why it matters for Lightbulb

- We aim for CPU-first, high-throughput inference. Hardware-aware kernel selection can deliver major latency/throughput wins without modifying model weights. This influences `kernels.rs` and the scheduler's kernel-selection logic.

Actions

1. Prototype a hybrid attention scheduler in `kernels/` that selects between at least two attention implementations based on sequence length and layer depth.
2. Add microbenchmarks under `bench/` that measure throughput and memory use for selected blocking parameters; include a small accuracy check (toy perplexity) to measure regressions.
3. Add a short developer note `docs/kernels/attention-scheduling.md` summarizing recommended heuristics and thresholds for CPU targets.

Acceptance criteria

- `kernels` exposes a kernel selector with runtime thresholds and a bench showing >=1.2x throughput on long sequences with <1% toy-task perplexity degradation.
- `docs/kernels/attention-scheduling.md` added with recommended heuristics and a plan for runtime autotuning.
