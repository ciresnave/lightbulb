
# 2508.06753v1 — Small-model CPU Variants Survey

TL;DR

Survey of strategies to make small transformer models performant on CPUs: quantization, pruning, kernel tiling, and operator fusion trade-offs. Survey of CPU-optimized model variants and microarchitectural techniques for efficient small-model inference on commodity hardware.

Why it matters

- Many deployment targets are CPU-only; this survey consolidates practical tips and benchmarks to guide engineering trade-offs.
- Shows practical kernel and memory-layout strategies we can adopt for CPU-first deployment and deterministic CI testing.

Key technical takeaways

1. Int8 quantization plus blocked kernels often yield the best CPU throughput/quality trade-offs.
2. Operator fusion and careful memory layout can outperform naive vectorized implementations.
3. Model distillation and adapters are cost-effective ways to shrink working sets.

Actions / Implementation steps for lightbulb

1. Collect the survey's recommended kernel patterns and benchmarks and translate them into microbenchmarks for our target CPUs.
2. Prioritize quantized blocked kernels and small fused primitives in the kernels module.
3. Prototype a small-model build target (reduced hidden dims / fused kernels) for Candle-backed inference.
4. Benchmark memory layout and blocking strategies on representative CPU cores.

Acceptance criteria

- Produce microbenchmarks showing throughput/latency trade-offs for the selected CPU targets and implement at least one fused/quantized path.
- A microbenchmark demonstrating >=15% throughput improvement on target CPU for a small LM compared to baseline implementation.
