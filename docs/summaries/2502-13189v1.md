
# 2502.13189v1 — Quantization Safety & Metrics

TL;DR

Proposes robust quantization validation metrics and safety checks (per-layer sensitivity scans, calibration-aware quantization) to avoid catastrophic failures when deploying int8/int4 kernels. Focuses on quantization safety: defining failure modes when aggressively quantizing (int4/int8), proposing metrics to measure representational fidelity per-layer, and recommending runtime checks to guard against catastrophic numeric drift.

Why it matters for Lightbulb

- Quantized kernels are core to our performance goals; this paper gives practical acceptance tests and per-layer metrics that should be added to our CI and loader validation.
- Lightbulb will support low-bit kernels and loading pipelines. Runtime safety checks and per-layer metrics reduce the risk of silently degraded outputs when using aggressive quantization for CPU inference.

Key technical takeaways

1. Per-layer sensitivity varies widely; global quantization often fails when a few sensitive layers dominate error.
2. Calibration-aware quantization (per-channel scale + bias correction) reduces accuracy regressions on sensitive layers.
3. Fast per-layer sensitivity scans (using small calibration batches) are sufficient to identify problematic layers for CI gating.
4. Automated rollback to a safer precision (int8 or fp16) per-layer can avoid catastrophic failures while retaining most speedups.

Actions / Implementation steps for lightbulb

1. Summarize recommended per-layer metrics (error norms, distributional shifts) and add a `quant/metrics.md` note.
2. Prototype a small `quant/checks` utility that computes quick per-layer sanity checks during loading and warns/falls back to a safer representation.
3. Add per-layer sensitivity sweep tooling to the loader to produce per-layer quantization error reports.
4. Integrate a CI gate that rejects int4 kernels when a layer's sensitivity exceeds a configurable threshold.
5. Add a per-layer sensitivity-sweep tool in the loader that runs small calibration batches and reports RMSE / KL divergence per-layer in CSV form.
6. Add per-layer rollback rules: mark layers to keep at higher precision when sensitivity exceeds threshold; provide an override file for manual tuning.
7. Integrate the sensitivity-sweep as an optional CI job for quantized loader artifacts; fail the build when thresholds are exceeded.
8. Provide a small visualization script for per-layer sensitivity heatmaps to help humans tune thresholds.
9. Wire a CI test that loads an aggressively-quantized tiny model and runs the sanity checks; fail CI if checks exceed thresholds.

Acceptance criteria

- `quant/metrics.md` added with at least three concrete per-layer metrics and suggested thresholds.
- `quant/checks` prototype added and tested on a toy quantized model with CI-friendly output.
- Implement a sensitivity-sweep runner producing a CSV report and a CI rule that fails when any layer exceeds the sensitivity threshold (default 1.5x baseline loss).
- Provide a visualization script and a documented workflow for resolving failing layers.
