# 2501.09223v2 — Latent-space routing / lightweight router

TL;DR

This preprint introduces a low-overhead router that makes routing decisions in a compact latent space (short context summaries) to select small expert modules. The emphasis is on minimizing decision latency and communication cost while preserving per-request quality.

Why it matters for Lightbulb

- A lightweight router helps enable conditional compute paths with low overhead, which is critical for per-request latency targets and for scaling capacity-aware MoE behaviors on CPU-centric stacks.

Actions

1. Implement a `engine::Router` trait sketch and a simple softmax-based router that can be plugged into the scheduler for experiments.
2. Add a microbenchmark in `bench/` that measures routing decision latency and routing accuracy vs an oracle routing label set.
3. Add a ROADMAP note describing when to prefer latent-space routing vs heavier MoE routing (cost thresholds, request sizes).

Acceptance criteria

- `engine::Router` trait added with a working softmax router and unit tests.
- Microbench demonstrating routing overhead <5% added latency on a toy model, or a documented decision to defer prototyping.
