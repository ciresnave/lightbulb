# 2509.13310v1 — reproducible CPU latency/throughput benchmarks (stub)

TL;DR

- Short summary: best practices and harnesses for reproducible CPU latency & throughput benchmarks.

Why it matters

- Reproducible microbenchmarks are essential for comparing kernels and tracking regressions.

Key takeaways

- Use pinned CPUs, fixed OS governor settings, and deterministic inputs to reduce noise.
- Collect percentile latencies and CPU counters to diagnose regressions.

Implementation steps

1. Add a small benchmarking harness to `tools/bench` or `bench/`.
2. Document CI policies for running these benchmarks consistently.

Acceptance criteria

- Benchmarks reproduce within acceptable variance on CI and local developer machines.
