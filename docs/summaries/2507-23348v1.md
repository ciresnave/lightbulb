## TL;DR

SWE-Debate introduces a competitive multi-agent debate framework for software issue resolution, leveraging graph-based fault localization and structured argumentation among agents. By generating multiple fault propagation traces and synthesizing modification plans through debate, it achieves state-of-the-art results on repository-level issue resolution benchmarks.

## Why it matters

- Addresses the limitations of single-agent approaches that get stuck in local solutions and miss cross-cutting issue patterns
- Provides a systematic, graph-guided method for fault localization, directly relevant to large codebases and ML infrastructure
- Demonstrates measurable improvements in both issue resolution rate and localization accuracy over strong baselines
- The debate mechanism surfaces architectural trade-offs and improves modification plan quality, aligning with lightbulb's goals of robust, efficient automation
- Integrates with existing agentic frameworks, making it practical for real-world ML/engineering workflows

## Key technical takeaways

1. **Graph-based fault localization:** Constructs static code dependency graphs to generate diverse fault propagation traces, improving localization accuracy
2. **Competitive multi-agent debate:** Agents propose, defend, and refine modification plans, systematically evaluating competing hypotheses
3. **Structured modification plans:** Debate produces actionable, prioritized plans that guide downstream patch generation (via MCTS)
4. **Empirical results:** Achieves 41.4% Pass@1 on SWE-Bench-Verified (6.7% improvement over baselines) and 81.67% file-level localization accuracy
5. **Ablation studies:** Show that multiple chain generation (+10%), edit plan (+6%), and debate (+4.2%) each contribute significantly to performance

TL;DR
Adaptive patience augments early-exit models with per-input difficulty estimators and dynamic thresholds so that deeper layers are used only when needed, improving compute-efficiency with small accuracy cost.

Why it matters

- Fixed early-exit thresholds waste compute or hurt quality; adaptive patience balances compute savings and accuracy per-input and under variable runtime budgets.

Key technical takeaways

1. Difficulty estimators (lightweight classifiers) can predict when shallow outputs suffice.
2. Adaptive thresholds tied to runtime budgets reduce wasted deeper computation under load.
3. Training small difficulty predictors is cheap and transfers across tasks with minor tuning.
