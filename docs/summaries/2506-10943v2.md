# 2506.10943v2 — Routing Overhead Evaluation

TL;DR
Measures routing overheads in several MoE and conditional compute systems, emphasizing that naive routers can dominate latency unless carefully optimized and loaded-balanced.

Why it matters

- Quantifies real-world router costs and provides microbenchmarks that help set routing latency budgets for CPU-first deployments.

Key technical takeaways

1. Simple dense projectors can be cheap but memory touches for experts often dominate latency.
2. Load balancing and budgeted routing reduce worst-case overheads significantly.
3. Telemetry (per-token routing latency, expert activation counts) is essential for diagnosing bottlenecks.

Implementation steps for lightbulb

- Add routing microbenchmarks to the router component to measure per-token latency and memory-touch costs.
- Implement budgeted routing defaults and a load-balancer fallback in the router prototype.
- Expose routing telemetry via tracing spans and logs.

Acceptance criteria

- Routing microbenchmarks present in the repo; default router reduces worst-case routing latency by at least 30% vs naive baseline on synthetic workloads.
