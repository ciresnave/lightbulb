# 2506.16500v1 — Sparse Mixture Routing Analysis

TL;DR

This paper analyzes sparse mixture-of-experts (MoE) routing, measuring load imbalance and proposing lightweight capacity-aware rebalancing and bucketing heuristics that reduce tail latency with low overhead.

Why it matters

- Naive MoE routers can catastrophically increase tail latency and memory pressure under skewed token distributions. This work provides practical mitigations that translate directly into runtime router defaults.

Key technical takeaways

1. Token skew amplifies expert imbalance; capacity caps prevent single-expert hotspots.
2. Lightweight bucketing of tokens (by score) reduces straggler variance with minimal routing overhead.
3. Aggressive rebalancing can hurt throughput; prefer conservative, budgeted reassignments.
4. Simple heuristics often match more complex optimizers in practice when tuned for realistic workloads.

Implementation steps for lightbulb

- Implement per-expert capacity limits and a two-stage selection: score-based bucketing then capacity-aware assignment.
- Add an instrumentation hook to record expert load histograms and rebalancing events.
- Provide a synthetic skewed workload benchmark to validate default settings.

Acceptance criteria

- Under synthetic skewed workloads, tail latency improves by >=20% and expert memory per-node stays within configured caps.
